# v0.1 draft hardening decisions

## Decision

Record the v0.1.0 draft hardening batch tracked by #247.

- Envelope-level token usage belongs on the first derived entry whose payload supports `usage` (`agent_message`, `agent_thinking`, or `tool_call`) and MUST NOT be repeated on later entries from the same source envelope (#248).
- The schema definition name remains `agentMessageUsage` for v0.1.0, even though the field is no longer exclusive to `agent_message`; renaming is deferred to avoid grammar churn (#248).
- The usage placement rule aligns with the existing inline-first / ref-subsequent source envelope convention: one source envelope has one first derived entry for shared envelope-level facts (#248).
- ADR numbering is append-only: session bundles remain ADR-0007, context compaction replacement provenance moves to ADR-0008, and this hardening batch is ADR-0009 (#247).

## Considered Options

- Keep usage only on `agent_message` (rejected: tool-call-only and thinking-only assistant envelopes lose token accounting).
- Allow usage on every event type (rejected: broader schema surface than v0.1.0 needs).
- Rename `agentMessageUsage` to `usage` immediately (rejected: unrelated generated-type and schema churn).
- Leave duplicate ADR-0007 files in place (rejected: ambiguous references as the draft approaches freeze).

## Consequences

- `schema.json`, the schema package artifact, generated TypeScript declarations, and validation fixtures allow `payload.usage` on `agent_message`, `agent_thinking`, and `tool_call`.
- Adapters preserve token usage for assistant envelopes whose first emitted entry is a thinking block or tool call.
- Future hardening decisions under #247 can extend this ADR with additional bullets instead of creating duplicate-number records.

Tracks #247 and #248.
